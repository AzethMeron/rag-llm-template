# Pinned Python environment for rag-llm-template.
#
# Recreate with: tools/setup_python_env.sh
#
# Every package is pinned exactly, transitive ones included. Pinning only the direct
# dependencies leaves the installed set free to drift, which is the drift that makes a
# months-old run impossible to reproduce (CLAUDE.md: pin and document the environment).
#
# The dependency footprint is deliberately small and grows one layer at a time, so the
# core stays importable with nothing installed. Optional feature blocks (dense retrieval,
# the vector database, alternative store drivers) are added by the milestone that first
# needs them, each behind a lazily-imported driver module so the core import path never
# pulls them. Resolved on Python 3.12.

# --- default vector database (LanceDB) + dense-vector math --------------------
# The default VectorIndex driver is LanceDB: a real, embedded vector database with true ANN
# indexing, no server or daemon. It is imported lazily inside store/vector/lancedb.py alone, so
# the core import path never pulls it, and tests/test_boundaries.py confines the allowance to
# that module. numpy is the dense-vector math used by the retrieval layer. Both are only needed
# for dense/vector retrieval; a pure-lexical (FTS5) run touches neither.
#
# pylance is a second, separate dependency of lancedb's own compaction path (Table.compact_files/
# optimize call table.to_lance(), which raises ImportError without it): a table built from many
# small incremental upserts (exactly reconcile_vector()'s write pattern on a long-running,
# resumed-many-times embed job) accumulates one small on-disk fragment per upsert batch, and
# without periodic compaction, every subsequent read/write against it re-opens/rescans the whole
# growing fragment list -- confirmed directly: legal_procurement's table had accumulated 3,717
# versions / 1,858 fragments for 2M rows, and simply *opening and reconciling against* that table
# was costing multiple GB of RSS per batch, before compaction (see tools/compact_vector_store.sh)
# brought it down to 2 fragments and fixed it. Not optional polish -- this repo's own vector
# stores need it.
lancedb==0.36.0
numpy==2.5.1
pylance==9.0.0
# transitive
annotated-types==0.8.0
deprecation==2.1.0
lance-namespace==0.8.6
